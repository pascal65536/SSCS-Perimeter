# Архитектура

## Границы контуров

### Эксплуатационный stateless-агент

`Perimeter Builder → settings.json → Collector → Spool → SIEM Gateway → OpenSearch`

- Builder разрешает корни через deps.dev v3 и дополняет узлы метаданными PyPI. Один узел на каноническое PEP 503‑имя; при пересечении графов сохраняется минимальная глубина, `perimeter_root` объединяется.
- Collector выполняет только получение, нормализацию, лёгкое enrichment и cursor‑дедупликацию цикла. Он не рассчитывает baseline, score или severity.
- Spool — временная очередь с ограничением байтов, а не система хранения. Подтверждение `ack` выполняется только после успешного bulk‑ответа. Ошибочные события направляются в DLQ.
- OpenSearch хранит телеметрию, эпизоды, риски, findings и feedback. `_id=event.id` исключает дубли при повторной доставке.

### Исследовательский контур

`analytics/` и `storage/` используются для воспроизводимых экспериментов, калибровки и PIT backtesting. SQLite из `storage/` не входит в эксплуатационный агент. Результаты исследования — веса, пороги и FP‑кривые — переносятся в `siem/content/catalog.json`.

### GUI Client

GUI является «линзой»: дерево происходит из `settings.json` или снапшота, риски и находки — из готовых выборок SIEM. Детекторов в GUI нет. LiveBackend и DemoBackend реализуют один интерфейс, поэтому дерево и панель деталей не знают источник данных.

Разрешённые записи:

1. `settings.json` — через `SettingsClient → SettingsManager`.
2. TP/FP — в `sscs-feedback` через LiveBackend.
3. Локальные заметки — `~/.sscs/notes.json`, вне SIEM.
4. Снапшот — по явной команде пользователя.

## Поток добавления пакета

1. Диалог возвращает имя и необязательную версию.
2. Settings Client канонизирует имя и идемпотентно добавляет root.
3. Фоновый QThread запускает Builder, не блокируя интерфейс.
4. Manager атомарно заменяет perimeter.
5. GUI перечитывает конфигурацию и выбирает добавленный узел.

## Надёжность и деградация

- HTTP 404 при построении — warning и пропуск; при мониторинге — `package.removed`.
- Ошибка одного пакета не отменяет цикл остальных.
- Недоступность SIEM оставляет элементы в Spool; GUI переходит в demo.
- Live API ограничены таймаутами и Retry-After; PyPI соблюдает интервал не менее 0,3 с.
- Секреты принимаются только из `GITHUB_TOKEN`, `SSCS_OPENSEARCH_TOKEN`, `SSCS_OPENSEARCH_USERNAME`, `SSCS_OPENSEARCH_PASSWORD` и не пишутся в JSON/логи.

## Детерминизм

- Идентификаторы событий строятся из устойчивых атрибутов источника.
- JSON сериализуется с сортировкой ключей; пакеты, зависимости и предупреждения сортируются.
- Исследовательский backfill сортирует JSONL-строки.
- `detector_config_hash` вычисляется по отсортированным путям и содержимому SIEM-контента.
- Время приёма можно зафиксировать через `--ingested-at`/`--generated-at` для повторяемых прогонов.
